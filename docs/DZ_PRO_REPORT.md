# ДЗ PRO — AI Контент-Мейкер  
## BOOK-CRAFT · Narrative AI Studio

**Репозиторий:** `VictorKVS/BOOKCRAFT-SITE`  
**Локальный адрес для проверки:** `http://127.0.0.1:5180/`  
**Текущая версия:** `0.4.2`  
**Стек:** React 18 · Vite 5 · React Router · CSS · configuration-driven visual assets

---

## 1. Цель работы

Цель проекта — собрать единое приложение **AI Content Maker**, в котором одна исходная идея может быть преобразована в несколько связанных форматов контента.

В BOOK-CRAFT реализованы отдельные рабочие модули для:

- рассылки;
- подкаста;
- видео-аватара;
- лонгрида;
- генерации изображений;
- книг и сценариев;
- аналитики и общего Create Hub.

Ключевая идея интерфейса: не набор несвязанных генераторов, а единый **narrative workflow** с общей визуальной и смысловой логикой.

---

## 2. Главная страница

Главная страница разработана как отдельная визуальная система BOOK-CRAFT.

Основные элементы:

- hero-блок с персонажем и сменяемыми визуальными слоями;
- live-текст и CTA поверх графической сцены;
- HUD-блоки аналитики, подкаста, контент-плана и видео-аватара;
- четыре image-first карточки продуктов;
- блок обязательных рабочих потоков;
- кнопка **«Смотреть демо»** с hover-меню.

При наведении на **«Смотреть демо»** открывается меню:

- **ТЕКСТ** → Рассылка;
- **АУДИО** → Подкаст;
- **ВИДЕО** → Видео-Аватар;
- **EXTRA** → Лонгрид;
- ссылка на полную карту демонстрации.

Главная является основным визуальным кадром проекта.

**URL:** `http://127.0.0.1:5180/`

## 3. Рассылка

**URL:** `http://127.0.0.1:5180/mailing?demo=1`

Пользователь задаёт:

- тему;
- аудиторию;
- цель;
- тон сообщения.

После запуска интерфейс показывает состояние обработки:

`brief → system prompt → generation → result`

Результат разделён на:

- `SUBJECT`;
- `PREHEADER`;
- `BODY`.

В DEMO-режиме кнопка запускает видимый процесс генерации, после чего появляется готовый вариант письма. Повторный запуск формирует альтернативный DEMO-результат.

---

## 4. Подкаст

**URL:** `http://127.0.0.1:5180/podcast?demo=1`

Входные параметры:

- тема или сценарий;
- формат;
- голос.

Интерфейс демонстрирует пайплайн:

`script → chunks → voice render → audio state`

После подготовки доступны:

- waveform;
- кнопка воспроизведения;
- progress bar;
- динамическое состояние DEMO PLAY.

Текущая реализация демонстрирует интерактивный TTS-workflow. Подключение реального TTS API является отдельным интеграционным этапом.

---

## 5. Видео-Аватар

**URL:** `http://127.0.0.1:5180/video-avatar?demo=1`

Рабочий сценарий:

`external service → catalog → avatar + voice → script → video job`

В интерфейсе предусмотрены:

- каталог аватаров;
- каталог голосов;
- выбор пары avatar/voice;
- поле сценария;
- подготовка video job;
- состояния loading / rendering / ready.

Для DEMO реализована интерактивная имитация получения каталога и формирования video job.

**Важно:** текущий интерфейс и API-contract готовы, но реальный запрос к HeyGen или другому provider API должен быть подключён и проверен отдельно. DEMO не выдаётся за live API.

---

## 6. Дополнительная вкладка — Лонгрид

**URL:** `http://127.0.0.1:5180/longread?demo=1`

Дополнительный модуль использует собственный workflow:

`тема + аудитория + тон → thesis → outline → narrative arc → longread draft`

В DEMO отображается процесс построения структуры и четыре смысловых раздела материала.

---

## 7. Бонус — генерация изображений

**URL:** `http://127.0.0.1:5180/images?demo=1`

Модуль содержит:

- текстовый prompt;
- стиль;
- aspect ratio;
- кнопку запуска;
- четыре визуальных варианта;
- выбор результата.

DEMO показывает стадии:

`prompt → composition → render → variants → select`

В дальнейшем этот интерфейс может быть связан с локальным ComfyUI/image backend.

## 8. Системные промпты

Системные промпты вынесены в отдельный исходный файл:

`src/prompts/contentMakerPrompts.js`

В нём определены:

- `mailingSystemPrompt`;
- `podcastSystemPrompt`;
- `videoAvatarSystemPrompt`;
- `longreadSystemPrompt`.

Таким образом prompt-контракты находятся в коде проекта и отделены от UI-компонентов.

---

## 9. Дизайн и архитектурный подход

В процессе разработки был применён подход:

`CARCASS → CARCASS LOCK → ASSET REGISTRY → VISUAL LAYERS → PROPORTION QA → INTERACTIVE DEMO`

Главная сцена собирается из независимых слоёв:

`background → character → books/cup → laptop → live UI → HUD`

Это позволяет заменять персонажа, одежду, предметы и сцену без переписывания React-интерфейса.

Для hero также реализована configuration-driven ротация визуальных вариантов.

## 15. Итог

В результате создан многостраничный прототип **BOOK-CRAFT Narrative AI Studio** с единым визуальным стилем, отдельными контентными workflow, интерактивными DEMO-состояниями, системными промптами и подготовленной схемой сдачи.

Проект уже можно демонстрировать локально как связанный продукт. Для полного закрытия production-части остаются два финальных действия:

1. подключить и проверить реальный внешний Video Avatar API;
2. опубликовать приложение и добавить публичную ссылку в отчёт.
