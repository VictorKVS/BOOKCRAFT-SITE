## Быстрый маршрут проверки

1. Сначала открыть `/` и снять главный кадр №00.
2. Затем открыть `/demo` и пройти остальные состояния по карте.
3. Делать скриншот при масштабе браузера 100%.
4. Для страниц с `?demo=1` ничего вводить не нужно — итоговое состояние подготовлено заранее.
5. Для отчёта использовать имена файлов из таблицы без переименования.

## Что закрывает требования ДЗ

- Рассылка — `/mailing?demo=1`
- Подкаст — `/podcast?demo=1`
- Видео-Аватар — `/video-avatar?demo=1`
- Дополнительная вкладка — `/longread?demo=1`
- Индивидуальный дизайн и логика — все страницы BOOK-CRAFT
- Самостоятельные системные prompt-контракты — `src/prompts/contentMakerPrompts.js`
- Бонусная генерация изображений — `/images?demo=1`

> Примечание: screenshot DEMO не следует выдавать за подтверждённый live API. Для финального требования по внешнему сервису Video Avatar реальный provider key/API должен быть подключён и проверен отдельно.


## Куда складывать файлы

Скриншоты сохраняем в репозитории:

`evidence/screenshots/`

Имена файлов должны точно совпадать с таблицей выше.

Локальный путь:

`G:\1\BOOKCRAFT-SITE\evidence\screenshots\`

Видео-демонстрацию сохраняем отдельно:

`evidence/video/BOOKCRAFT_DZ_PRO_DEMO.mp4`

Локальный путь:

`G:\1\BOOKCRAFT-SITE\evidence\video\BOOKCRAFT_DZ_PRO_DEMO.mp4`

Если MP4 получается слишком большим для обычного Git push, в репозитории оставляем README и ссылку на опубликованное видео, а сам MP4 храним отдельно.
